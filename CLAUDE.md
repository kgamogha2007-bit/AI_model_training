# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A small PyTorch image classifier that recognizes a cricket umpire's signal — `out`, `six`, or `wide` — from a single photo. Fine-tunes a torchvision `resnet18` (ImageNet-pretrained) with a replaced final layer for 3 classes.

## Setup

```
python -m venv venv
venv\Scripts\activate          # Windows
pip install -r requirements.txt
```

`requirements.txt` is a raw `pip freeze` from the dev environment, not a curated dependency list — it's missing `torch`/`torchvision` (both required to run any script here) and includes unrelated packages (`openai`, `pygame`, `wxPython`, `pyicloud`, `icrawler`...). Install `torch`/`torchvision` separately (see https://pytorch.org/get-started/locally/ for the right build for your CUDA/CPU setup) before running anything.

## Commands

```
python setup_folders.py   # creates data/train|val/{out,six,wide}
python scrape_images.py   # Bing image search -> data/scraped/<class>/ (staging, needs manual review)
python extract_frames.py --sources sources.txt   # video frames -> data/scraped/<class>/frames_.../ (staging)
python train.py           # trains resnet18, writes best_model.pt
python test_model.py      # evaluates best_model.pt against data/test
```

There is no test suite (`pytest` in requirements.txt is unused), no linter, and no build step.

`scrape_images.py` and `extract_frames.py` never write into `data/train` or `data/val` directly — they populate `data/scraped/<class>/` as a staging area (with a `dedup.py` near-duplicate pass applied automatically) because scraped/extracted candidates are noisy and need a manual culling step before being promoted into the curated splits.

## Architecture

- **`setup_folders.py`** — one-time scaffolding for `data/{train,val}/{out,six,wide}/`. Images must be placed into these folders manually (or via a separate scraping step) before training; this repo has no data-collection script.
- **`train.py`** — loads `data/train` and `data/val` via `torchvision.datasets.ImageFolder` (class labels are inferred from subfolder names), fine-tunes `resnet18` for 15 epochs with SGD + step LR decay, and saves the best validation-accuracy checkpoint as `best_model.pt` (state_dict only, not the full model).
- **`test_model.py`** — rebuilds the same `resnet18` architecture, loads `best_model.pt`, and reports per-image predictions plus overall accuracy against `data/test`.
- **`best_model.pt`** — checkpoint committed at the repo root; regenerated by `train.py`.

## Data layout gotcha

`data/test` uses capitalized class folder names (`Out`, `Six`, `Wide`) while `data/train` and `data/val` use lowercase (`out`, `six`, `wide`). Because `ImageFolder` sorts class names alphabetically per-split and both casings happen to sort into the same relative order (out/Out, six/Six, wide/Wide), the label *indices* still line up correctly — but this inconsistency is easy to trip over if more classes are added later. Prefer lowercase for any new class folders.

## Dataset size

The dataset is very small (currently ~70 train / ~16 val / ~14 test images total across 3 classes), so accuracy numbers from `test_model.py` will be noisy — treat them as directional, not statistically meaningful, until the dataset grows.
